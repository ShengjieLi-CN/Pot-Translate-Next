# 3.1.2 同声传译与自定义 STT

主窗口左侧“输入翻译”下方进入“同声传译”。先展开“STT 模型设置”，填写自己的兼容接口地址、模型名称、API Key（本地服务可留空）和返回格式，保存后选择已有文本翻译服务。应用不附带 STT 模型权重或预置 API Key。

点击“测试模型”可用当前填写的配置（无需先保存）发送一段内置英文合成语音，检查接口、模型及返回格式，并显示耗时和转写结果。不会录制麦克风或系统声音，不会调用翻译服务，也不会自动保存配置。接口返回空转写时显示“已连通，但未识别出测试语音”，不会直接判定识别功能正常。修改配置后清除旧测试结果。测试可能产生一次转写费用；单人测试音频不能验证多人分离效果。

Windows 支持当前默认播放设备的系统声音，以及默认麦克风。开始后持续采集，按可配置的 3–30 秒片段转写并翻译；默认 8 秒，每段带 0.75 秒重叠。实际字幕延迟是分段时间加上服务响应时间，属于连续分段同传，接口无需提供 WebSocket。模型的分句、时间戳和说话人分离质量决定最终效果。

暂停、继续和结束会保留已录音频及转写记录；结束后继续处理已经排队的片段。录音、转写、译文都不会在进入页面时自动开始。处理落后时会暂停采集并保留队列；服务失败可修正设置后重试。离开同传页面会停止采集并忽略未完成请求的后续结果。已发到服务端的请求可能仍会完成。转写记录和录音在本次应用运行期间保留，需要长期保存时请导出。

支持导入音频、回放、点击时间戳定位、重命名讲话人、导出双语 TXT / SRT / JSON 和保存 WAV。单次会话或音频文件最长 30 分钟，导入文件最大 100MB。系统声音采集会包含当前默认输出设备上其他应用的声音；回放音频前请暂停实时采集，避免再次识别回放内容。

## HTTP 协议

请求为 `POST`，`multipart/form-data`：

| 字段 | 内容 |
| --- | --- |
| `file` | 文件名 `live.wav`，单声道 16kHz PCM16 WAV |
| `model` | 用户填写的模型标识 |
| `response_format` | `diarized_json`、`verbose_json` 或 `json` |
| `language` | `en`、`zh` 等语言代码；自动检测时省略 |
| `stream` | `false`，客户端连续分段调用 |
| 附加字段 | 设置中的 JSON 对象；数组写为重复的 `字段名[]` |

API Key 非空时以 `Authorization: Bearer ...` 发送。地址必须为 HTTP/HTTPS，不能在 URL 中嵌入用户名、密码；请求不跟随重定向，不记录音频和访问凭据。附加 JSON 不能覆盖上述核心字段及说话人参考音频字段。默认请求超时为 60 秒。

成功响应须为 JSON，使用秒为时间单位，时间戳相对于当前上传片段：

```json
{
  "language": "en",
  "segments": [
    {
      "start": 0.0,
      "end": 2.7,
      "text": "Welcome to the seminar.",
      "speaker": "A",
      "speaker_embedding": [0.1, 0.8, 0.2]
    },
    {
      "start": 2.8,
      "end": 5.8,
      "text": "Could you explain the method?",
      "speaker": "B",
      "speaker_embedding": [0.9, 0.1, 0.2]
    }
  ]
}
```

也支持 `utterances`、`transcript`、`speaker_id`、`start_time` / `end_time`，以及顶层 `speaker_embeddings` 按说话人标签返回向量。只返回 `{"text":"..."}` 的模型可以转写和翻译，但没有说话人信息时会明确显示“说话人未识别”，不会假设音高或音量代表身份。

## 区分说话人

1. **声纹向量**：推荐自定义服务返回同一个声纹编码器产生的 `speaker_embedding`。客户端按余弦相似度关联跨片段说话人，阈值可配置，默认 0.8；阈值需要针对实际编码器校准。原始向量不会自动当作真实姓名。
2. **会话级 ID**：服务必须保证当前会话中返回的 `speaker` / `speaker_id` 跨请求保持稳定。需要会话标识的服务可以在附加 JSON 里配置其要求的 `session_id`。
3. **片段标签 + 重叠语音**：A/B 等标签仅在当前片段内有效。客户端可利用重叠的已识别语段关联，缺少对应证据时分配新编号，不把每次的 A 都当作同一人。独立片段或间隔较长的声音需要声纹或参考音频才能可靠关联。

接口支持时，可以勾选“发送说话人参考音频”。应用最多选取四位讲话人各 2–8 秒的片段，以 `known_speaker_names[]` 和 `known_speaker_references[]`（WAV data URL）随之后的请求发送。如果接口不支持这些字段，应取消勾选。设置中的“填入兼容说话人分离示例”可填写相应协议示例，API Key 仍需自行提供。

音频只发送至用户配置的 STT 接口，原文只发送至所选翻译服务；语言自动检测优先采用 STT 结果，否则使用本地语言检测。

参考协议：[官方 STT / 说话人分离说明](https://developers.openai.com/api/docs/guides/speech-to-text#speaker-diarization)，[Windows 系统声音回环采集](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)。

## 验证和本地更新

- `pnpm test`：36 项前端测试，包含声音分段、WAV 编码、时间戳、声纹匹配、说话人标签、重叠去重、字幕导出、排队和失败恢复。
- `.scripts/verify-live-ui.cjs`：Playwright 使用合成音频与模拟 STT / 翻译验证真实页面，不使用个人 API Key。预览同样采用模拟服务，不能用来判断模型转写和翻译准确率。
- Rust 原生测试验证 multipart 请求，以及真实 Windows 默认输出设备打开、PCM 采集和停止。音频采集测试需显式运行被忽略的 `windows_loopback_opens_captures_pcm_and_stops`。
- `.scripts/build-local.ps1` 编译与已安装版本具有相同应用标识的本地程序，明确使用 `--bundles none`，不生成安装包。

真实自定义 STT 服务尚未配置，端到端识别准确率及模型的说话人分离效果待用户接入后检查。当前原生采集针对 Windows；其他平台可使用音频文件导入。
