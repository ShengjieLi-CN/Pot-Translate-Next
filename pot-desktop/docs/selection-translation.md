# 划词翻译

Windows 默认启用划词按钮：在 PDF、浏览器、文档中拖选或双击选中文字后，鼠标附近出现“译”。点击后显示独立译文浮窗；选中文字本身不会发送到翻译服务。主窗口“划词翻译”可关闭按钮、选择已有翻译服务和目标语言。原有“划词翻译”快捷键也进入同一个仅译文浮窗。

译文按原文段落组织，不拆分成逐句卡片，也不显示原文。PDF 的视觉断行合并成连续段落，换行连字符会恢复，服务额外输出的换行在单个段落内合并；窗口内允许自然折行。复制保留段落之间的空行。标题、列表和来源应用能够提供的段落字体、字号、粗体、斜体用于显示译文。不同语言的字数、字体字形和字宽不同，不保证与原文逐字逐行对齐；来源应用未提供的排版属性不会凭空重建，段内混合强调不保证逐词对应。

鼠标按下/抬起通过 Windows 低级鼠标事件监听，而不是定时轮询按键状态，避免快速划词和双击漏检。拖选/双击后先显示非激活的“译”按钮，显示按钮不依赖来源应用的 TextPattern 支持，也不读取或发送正文；标题栏、常见滚动条/按钮/文件列表和标准密码编辑框会被排除。无法确定是否确有文本选区的自绘文档也会提供按钮，点击后若读不到文字会提示重选或截图翻译。

点击按钮后才通过 UI Automation TextPattern / GetSelection 读取文字，并从选区附近、焦点元素及其文档节点查找。格式通过 TextUnit_Format 和 GetAttributeValue 读取；格式 API 不可用时保留已获取的纯文本，不丢弃整个选区。若直接读取失败，则在保存的来源窗口中使用现有 selection 库兼容复制取词，并恢复原剪贴板文本或图片。按钮不抢走原文焦点；不会向译文窗口发送取词操作。扫描 PDF 需使用截图翻译。主窗口会提示监听初始化失败。

点击“译”后立即展开浮窗显示取词进度；取词期间浮窗不激活，保留来源文档焦点。UIA 超过 1.8 秒仍不响应时转用兼容复制，后台最多保留一个 UIA 取词任务，避免不响应的 PDF 阻塞后续请求。取词返回后会重新核对当前选区和来源窗口，关闭或重新划词后不执行旧请求的复制操作，也不会显示旧结果。快捷键使用相同的取词、进度和失败重试流程。结果浮窗支持 Escape 关闭。

划词设置会明确显示“已关闭”或“监听已就绪”，关闭时提供直接启用按钮。加载、取词失败、翻译失败和成功状态均不展示原文；本地 AI 插件使用本次请求专用的仅译文提示词，不覆盖已保存的服务设置。

点击页面空白处或关闭按钮隐藏浮窗。划词按钮约 10 秒后自动消失。新选区使旧请求失效，旧请求的延迟返回不会覆盖新译文。文本只在点击“译”或按划词快捷键后发送到设置中选择的服务；语言检测在本地进行。不会修改翻译服务已保存的提示词。

验证：`node --test tests/*.test.mjs`，`.scripts/verify-selection-ui.cjs`（含延迟取词、取词失败/重试和监听故障提示，使用合成选区与模拟服务，不使用个人 API Key）。Rust `selection_translate::` 测试覆盖快速/反向拖选、双击、跨窗口隔离、时间计数回绕和实际 Win32 鼠标钩子注册/移除。本地构建仍使用 `.scripts/build-local.ps1`，保持 3.1.2，不生成安装包。

API 依据：[Microsoft UI Automation text ranges](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-usingtextrangeobjects)。
